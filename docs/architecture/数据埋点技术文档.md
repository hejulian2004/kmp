> **文档版本**：1.0.0

> **适用模块**：`shared` (`commonMain`, `androidMain`, `iosMain`), `composeApp`, `androidApp`, `iosApp`

## 1. 架构目标与核心设计原则

### 1.1 系统定位
数据埋点基础设施位于 `shared` 模块的底层核心包（`org.example.project.core.analytics`），为全项目所有业务模块（如 FeedLine、Instagram、Airbnb）提供标准化、跨平台、统一上报的公共服务。

### 1.2 核心设计原则
1. **应用单例模式 (App Singleton Pattern)**：全应用共享唯一的 `AppAnalyticsManager` 示例，提供统一的调用的接口与全局环境参数注入。
2. **写前本地落盘与实时尝试 (Write-Ahead Persistence & Immediate Dispatch)**：触发埋点时先落盘入库，保证在弱网、断网或崩溃场景下数据不丢失；同时发起实时异步 HTTP 请求。
3. **逻辑删除与定容淘汰 (Logical Deletion & Capacity Pruning)**：上报成功后更新本地数据库记录状态为 `SUCCESS`（逻辑删除），保留历史日志；当总记录数超出配置上限时，按先进先出 (FIFO) 自动淘汰最旧的历史记录。
4. **强依赖顺序约束 (Strict Initialization Sequence)**：数据埋点单例必须在底层网络架构与本地数据库单例初始化完成后方可初始化。
5. **高性能与非阻塞 (Asynchronous Non-Blocking)**：基于 Coroutines 异步通道缓冲分发，严禁阻塞 UI 主线程或影响 Compose 120Hz 高刷体验。

## 6. 实时上报、逻辑删除与定容淘汰机制

```
                              用户触发埋点事件
                                    |
                                    v
                     +------------------------------+
                     | 1. 写入 Room 数据库本地持久化  |
                     | ( status = PENDING / 0 )     |
                     +--------------+---------------+
                                    |
                                    v
                     +------------------------------+
                     | 2. 异步发起实时 HTTP 请求      |
                     +--------------+---------------+
                                    |
                     +--------------+--------------+
                     |                             |
              (HTTP 200 成功)               (网络异常/超时/断网)
                     |                             |
                     v                             v
     +-------------------------------+   +-------------------------------+
     | 逻辑删除: 更新 status=SUCCESS |   | 保留记录于 Room 数据库          |
     +---------------+---------------+   | ( status = FAILED, retry+1 )  |
                     |                   +---------------+---------------+
                     v                                   |
     +-------------------------------+                   v
     | 3. 定容淘汰:                  |   +-------------------------------+
     | 若记录数 > maxRetentionCount  |   | 4. 定期重试机制:              |
     | 自动 FIFO 清理旧 SUCCESS 记录  |   |    后台定时拉取 FAILED 批量补发 |
     +-------------------------------+   +-------------------------------+
```

### 6.1 步骤与调度规范
1. **写前持久化 (Write-Ahead Persistence)**：
   - 触发 `trackEvent()` 时，协程优先将数据存入 Room `analytics_events` 表，初始状态记为 `PENDING`。
   - 随后发起异步 Ktor HTTP 上报请求。
2. **逻辑删除更新 (Logical Deletion)**：
   - 上报成功后，使用逻辑删除更新记录状态为 `SUCCESS`，禁止直接执行物理 `DELETE`。
   - 上报失败时，将状态置为 `FAILED` 并自增 `retry_count`。
3. **定容淘汰策略 (Capacity Pruning)**：
   - 本地最多保留条数由 `AnalyticsConfig.maxLogRetentionCount` 设定（默认 1000 条）。
   - 数据库记录总数超出上限时，按先进先出 (FIFO) 原则优先物理清理最旧的 `SUCCESS` 状态历史记录，保证存储空间稳定可控。
4. **失败定期重试 (Periodic Retry)**：
   - 后台定时轮询（如每 60 秒）拉取 `status == FAILED` 的记录，执行批量重发；成功后同样更新状态为 `SUCCESS` 并触发定容检测。

#### A.2 `AppAnalyticsManager.kt` (全局单例实现)

```kotlin
package org.example.project.core.analytics

import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.IO
import kotlinx.coroutines.launch
import kotlin.time.Clock

object AppAnalyticsManager : AnalyticsTracker {
    private var isInitialized = false
    private var config: AnalyticsConfig? = null
    private val trackers = mutableListOf<AnalyticsTracker>()
    private val globalParams = mutableMapOf<String, Any>()
    private val scope = CoroutineScope(Dispatchers.IO)

    fun init(config: AnalyticsConfig) {
        if (isInitialized) return
        isInitialized = true
        this.config = config
        
        globalParams["platform"] = config.platformName
        globalParams["app_version"] = config.appVersion
        globalParams["device_id"] = config.deviceId

        trackers.clear()
        trackers.addAll(config.trackers)
    }

    fun setUserContext(userId: String?, userRole: String? = null) {
        if (userId != null) {
            globalParams[AnalyticsParams.USER_ID] = userId
            userRole?.let { globalParams["user_role"] = it }
        } else {
            globalParams.remove(AnalyticsParams.USER_ID)
            globalParams.remove("user_role")
        }
    }

    fun trackScreenView(screenName: String, extraParams: Map<String, Any> = emptyMap()) {
        val params = extraParams.toMutableMap()
        params[AnalyticsParams.SCREEN_NAME] = screenName
        trackEvent(AnalyticsEvents.ENTER_SCREEN, params)
    }

    override fun trackEvent(eventName: String, params: Map<String, Any>) {
        val fullParams = globalParams.toMutableMap().apply {
            putAll(params)
            put("timestamp", Clock.System.now().toEpochMilliseconds())
        }

        val targetTrackers = if (trackers.isNotEmpty()) trackers.toList() else listOf(LogAnalyticsTracker())

        scope.launch {
            targetTrackers.forEach { tracker ->
                runCatching {
                    tracker.trackEvent(eventName, fullParams)
                }.onFailure { ex ->
                    println("AppAnalyticsManager 错误: Tracker 分发失败: ${ex.message}")
                }
            }
        }
    }
}
```

### 附录 B：Room 逻辑删除与定容淘汰 SQL 参考

```kotlin
@Entity(tableName = "analytics_events")
data class AnalyticsEventEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    @ColumnInfo(name = "event_name") val eventName: String,
    @ColumnInfo(name = "params_json") val paramsJson: String,
    @ColumnInfo(name = "status") val status: String = "PENDING", // PENDING, SUCCESS, FAILED
    @ColumnInfo(name = "retry_count") val retryCount: Int = 0,
    @ColumnInfo(name = "timestamp") val timestamp: Long
)

@Dao
interface AnalyticsDao {
    // 写入新埋点 (写前持久化)
    @Insert
    suspend fun insertEvent(event: AnalyticsEventEntity): Long

    // 逻辑删除：将状态修改为 SUCCESS
    @Query("UPDATE analytics_events SET status = 'SUCCESS' WHERE id = :id")
    suspend fun markAsSuccess(id: Long)

    // 上报失败：更新状态为 FAILED 并增加重试次数
    @Query("UPDATE analytics_events SET status = 'FAILED', retry_count = retry_count + 1 WHERE id = :id")
    suspend fun markAsFailed(id: Long)

    // 查询待轮询重试记录
    @Query("SELECT * FROM analytics_events WHERE status = 'FAILED' AND retry_count < 5 ORDER BY timestamp ASC LIMIT 20")
    suspend fun getFailedEventsForRetry(): List<AnalyticsEventEntity>

    // 定容淘汰修剪：超过 maxCount 时先进先出 (FIFO) 清理旧 SUCCESS 记录
    @Query("""
        DELETE FROM analytics_events 
        WHERE id IN (
            SELECT id FROM analytics_events 
            WHERE status = 'SUCCESS' 
            ORDER BY timestamp ASC 
            LIMIT MAX(0, (SELECT COUNT(*) FROM analytics_events) - :maxCount)
        )
    """)
    suspend fun pruneOldSuccessLogs(maxCount: Int)
}
```
